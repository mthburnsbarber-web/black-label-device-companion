# Windows clipboard helper: source only

This .NET 8 Windows desktop helper is not built, installed, or invoked in this workspace. `native/windows.js` is disabled until explicit `activate({consent:true})` and requires the absolute path of a separately built helper executable. The current CLI remains macOS-only. JavaScript mock tests cover the process contract; no Windows hardware or real clipboard has been tested.

The helper uses `CF_UNICODETEXT` and returns bounded UTF-8 bytes as Base64 with the Windows clipboard sequence number. A write receives UTF-8 on stdin, opens the clipboard with an owned hidden window, compares the expected sequence while it has the clipboard open, and writes Unicode text. It rejects embedded NUL because `CF_UNICODETEXT` is NUL-terminated. A failed `SetClipboardData` after `EmptyClipboard` can leave the previous clipboard content lost; the helper reports `write_failed_after_empty`, so the application must never describe that outcome as verified. It does not capture global input or inject keys or mouse events.

Before enabling Windows: build on an authorized Windows device, review the P/Invoke signatures and binary signing, test native Unicode and the 65,536-byte UTF-8 boundary, sequence races, occupied/denied clipboard, process restart and readback, and decide how to package the helper without automatic installation or autostart. Microsoft documents [the sequence number](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber), [OpenClipboard ownership](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard), and [SetClipboardData memory transfer](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setclipboarddata).
