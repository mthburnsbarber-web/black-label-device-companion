## Credentials and owner approval

1. In Cloudflare, create **one service token per Mac**, authorized only by the device Service Auth policy. Michael handles the one-time secret display and puts each token's client ID and secret into the corresponding Mac's Keychain under the configured service names. Do not put either value in this repository, chat, command arguments, environment variables, browser storage, or D1.
2. Council owner creates a five-minute invitation for each device. Its `pairingId`, `deviceId`, and one-time `code` are returned by `POST /api/http-relay/pairings`. Set each native config's `deviceId` to that exact returned UUID. The optional `--enroll <config> <pairing-id>` command prompts without echo for the one-time code, reads only the named Keychain token items, and submits `/enroll`. It returns `pending_owner_approval`, never paired status. It has **not** been used against Cloudflare.
3. On each physical Mac, compare the locally displayed 64-hex SHA-256 service-credential fingerprint with the owner-only Council pending-pairing view through an independent channel. Council binds the service-token digest to the approved device after the owner calls `/api/http-relay/pairings/:id/approve` with that exact fingerprint. This proves possession of the service token; it is not hardware attestation.
4. Generate a distinct, high-entropy 32-byte pair key in a user-approved method and place the same key in **both** Macs' Keychains under each other's configured peer-service name. Its Base64 form must decode to exactly 32 bytes. `--pair-check <config> <paired-device-id>` only prints the SHA-256 fingerprint, not the key. Compare both outputs out of band. The Council owner authorizes each desired direction separately via `/api/http-relay/pairs` with both approved device UUIDs and the matching key fingerprint. Key generation and secret transfer are intentionally not automated in this repository; the exact secure handoff still needs review.

## Manual text-only pilot

- Start each companion only after credentials, Council deployment, fingerprint checks, a reviewed compiled macOS clipboard helper in an absolute path, and explicit local clipboard opt-in are complete. The CLI is manually started; no installer, login item, launch agent, VPN, accessibility permission, keyboard capture, or mouse injection is included. It polls outbound HTTPS; no inbound home/office port is required.
- Use only harmless test strings. Send manually with `send <target-device-id>`. Test one character, multiline, Unicode, and the 65,536-byte UTF-8 limit. Verify the destination's `received`, `applied`, and `verified` states separately; queued frames are not proof of clipboard write. Then test stale revision, target clipboard change, pause, disconnect/reconnect, and denial on both Macs. Record only metadata and test outcome, not clipboard text or secrets.
- `pause` or `quit` locally stops the companion. Council's owner pause blocks traffic and clears queued frames. For revocation, stop both clients, revoke the device in Council, revoke its Cloudflare service token, remove its Keychain token and pair-key items, and verify old credentials fail. A new key is required before re-pairing.
